## 6. 小芽当前说话逻辑

### 6.1 硬件端

硬件主程序大致流程：

1. 每 10 秒读取云端 `/latest`，同步 `llm_enabled`。
2. 如果没有正在播放 MP3、没有等待 TTS、距离上次说话已超过 30 秒，则进入说话流程。
3. 如果 `llm_enabled = true`：
   - 硬件向后端 `POST /plant` 上传当前传感器状态。
   - 后端返回文字。
   - 硬件更新 OLED 状态并等待 TTS。
   - TTS ready 后播放 `/audio/latest.mp3`。
4. 如果 `llm_enabled = false`：
   - 硬件不调用大模型。
   - 直接从服务器预设 MP3 库中按当前状态随机播放一条。
5. 如果服务器或 AI 失败：
   - 硬件尝试播放当前状态的预设 MP3 兜底。

预设 MP3 路径形式：

```text
/audio/library/idle_01.mp3
/audio/library/need_sun_03.mp3
/audio/library/walking_07.mp3
```

### 6.2 后端端

后端接口：

```text
POST /plant
GET /latest
GET /settings/llm
POST /settings/llm
```

`POST /plant` 逻辑：

1. 解析硬件上传的传感器数据。
2. 读取 `llm_enabled`。
3. 如果 LLM 开启，调用 `generate_speech(ctx)`。
4. 如果 LLM 关闭，调用规则文案 `generate_rule_speech(ctx)`。
5. LLM 开启时，调用 TTS 生成 `latest.mp3`。
6. 更新 `latest_message`，供前端和硬件轮询。

TTS 音色：

```text
longhuhu_v3
```

### 6.3 LLM 与闲聊概率

当前后端：

```python
CHITCHAT_CHANCE = 0.25
```

也就是说：

- 25% 概率使用状态闲聊预设文案。
- 75% 概率调用百炼 `qwen-plus` 实时生成。
- 如果大模型失败，会退回规则文案。

注意：

- 25% 状态闲聊不是 MP3 预设库，它仍会走 TTS 合成。
- 如果希望每次联网都由大模型生成，可将 `CHITCHAT_CHANCE` 改为 `0`。

## 7. Walk 建议逻辑

当满足以下条件时，后端会考虑生成出门建议：

```text
state in idle / wilted / need_sun
place == indoor
```

出门建议倾向：

- 50% `light`，对应 Light Walk。
- 20% `sound`，对应 Sound Walk。
- 20% `color`，对应 Color Walk。
- 10% `local`，对应 Local Discovery。

后端会写入：

```text
suggested_walk_type
```

软件端可根据该字段联动推荐对应 walk 类型。

## 8. LLM 开关问题与修复

曾发现问题：

- 云端 `/latest` 返回 `llm_enabled: false`。
- 导致硬件一直播放预设 MP3，看起来像没有接入大模型。

进一步发现：

- 云端 Docker 使用 gunicorn，配置为 2 个 worker。
- 原先 `llm_enabled` 存在 worker 内存状态不同步的问题。
- 可能出现 `POST /settings/llm` 写入 true，但另一个 worker 的 `/latest` 仍返回 false。

已在本地修复：

```text
backend/utils/storage.py
```

修复方式：

- `get_llm_enabled()` 每次从持久化 JSON 同步 `llm_enabled`。
- 避免两个 worker 各自持有不同内存状态。

注意：

- 该修复需要提交并部署到云端，才会长期稳定。

## 12. 移动电源问题判断

现象：

```text
接 M5Stack ATOM TailBat 后：
S3R 屏幕亮
OLED 不亮
光照传感器没反应
```

判断：

- 大概率不是代码问题。
- 更可能是 Grove / PaHUB / I2C 外设供电没有起来。

原因可能包括：

- TailBat 190mAh 容量和瞬时电流不足。
- TailBat 只稳定带起了主控，没有稳定带起 PaHUB 外设链路。
- Grove 接口接触不良。
- 电池供电时启动时序较慢，外设初始化时还没稳定。

建议：

- 用 USB-C 给 S3R 供电验证外设是否正常。
- TailBat 供电时只接 OLED 或只接光照传感器测试。
- 用万用表测 PaHUB Grove 供电。
- 更稳的移动方案是使用容量更大的 5V USB 充电宝给 S3R USB-C 供电。
